# Balancing_Robot

STM32F411 과 MPU6050 으로 만든 2륜 밸런싱 로봇. **아직 서지 못합니다.**
중심을 잡으려는 동작까지는 갔고, 진동을 못 잡은 상태에서 취업이 되어 중단했습니다.

2025.12.19 – 12.30 · 커밋 21개

---

## 지금 어디까지 왔나

| | |
|---|---|
| 센서 각도 읽기 | 된다 — 상보필터로 가속도와 자이로를 합쳐 100 Hz 로 |
| 모터 구동·방향 | 된다 |
| 기울면 반응하기 | **된다** — 넘어지는 쪽을 스스로 받치려고 움직인다 |
| 서 있기 | **안 된다** — 떨림이 심해 중심을 잡기 전에 넘어진다 |

마지막 커밋 메시지가 그대로 상태입니다 — *"튜닝중... 여전히 떨림이 너무 심함."*

## 제어 구조

**100 Hz 루프** (`HAL_GetTick` 으로 10 ms 마다).

**각도** — 가속도만 쓰면 흔들림에 튀고, 자이로만 쓰면 시간이 갈수록 밀립니다.
그래서 상보필터로 섞습니다.

```c
Acc_Angle     = atan2f(Acc_X_Raw, Acc_Z_Raw) * 57.296f;
Gyro_Rate     = -Gyro_Y_Raw / 131.0f;
Current_Angle = 0.96f * (Current_Angle + Gyro_Rate * Loop_Time)
              + 0.04f * Acc_Angle;
```

MPU6050 의 DLPF 는 `0x03` 으로 두어 약 42 Hz 이상 진동을 센서 단에서 걸러냅니다.

**PID** — 지금 값은 `Kp 380 · Ki 0 · Kd 12`, 목표각 `-2.0°`(수직일 때의 센서 오차).
`Ki` 가 0 이라 실제로는 PD 제어입니다. 누적 제한(±2000)과 리셋 코드는 넣어 뒀습니다.

**안전장치** — 40° 넘게 기울면 모터를 끄고 적분항을 0 으로 되돌립니다.
넘어져 있는 동안 오차가 계속 쌓여 다시 세울 때 튀는 것을 막으려고 넣었습니다.
튜닝을 반복하려면 이게 있어야 편했습니다.

---

## 튜닝하면서 찾은 것

**1. 바퀴가 넘어지는 쪽으로 돌고 있었다**
기울이면 받쳐야 하는데 오히려 넘어지는 방향으로 굴렀습니다. 모터 회전 방향을 뒤집어 고쳤습니다.

**2. 자이로 부호가 반대였다** ← 여기가 제일 오래 걸렸습니다
방향을 고친 뒤에도 못 섰습니다. PID 계산식에 음수를 넣어 봤더니 서는 듯한 모습이 나왔는데,
계산식을 뒤집어서 되는 거라면 **입력 어딘가의 부호가 반대**라는 뜻이었습니다.
모터 방향을 다시 테스트해 보니 모터는 맞았고, 남은 건 센서였습니다.
자이로 각속도에 음수를 붙이니(`-Gyro_Y_Raw`) 그때부터 중심을 잡으려는 동작이 나왔습니다.

**3. 모터에 데드존이 있다**
PWM 을 조금 주면 바퀴가 아예 안 굴렀습니다. 값을 올려가며 재보니 **300 근처에서** 움직이기
시작했고, 여유를 둬서 **750** 을 항상 더해 주도록 했습니다.
PID 출력이 작을 때 아무 일도 일어나지 않는 구간을 없애려는 것입니다.

## 남은 문제 — 떨림

서지 못하는 이유는 **떨림**입니다. 중심 근처에서 앞뒤로 크게 흔들리다 넘어집니다.
실물로 확인하지는 못했고, **아래는 코드에서 짚이는 것이지 검증한 것이 아닙니다.**

**가장 의심스러운 것은 데드존 750 입니다.** 지금 값으로 계산해 보면 이렇습니다.

| 기울기 오차 | 모터에 나가는 값 | 듀티 (최대 4999) |
|---|---|---|
| 0° | 0 | 0 % |
| **0.1°** | 38 + 750 = **788** | **15.8 %** |
| 1° | 380 + 750 = 1130 | 22.6 % |

오차가 0 을 지나는 순간 출력이 0 에서 ±788 로 튑니다. 거의 수직인 0.1° 에서도 바퀴에
16 % 를 때리니, 반대로 넘어갔다가 또 튀는 것을 반복하게 됩니다.
**직접 재서 300 에서 움직인다고 확인해 놓고 750 을 쓴 것**이 과합니다.
데드존 보상 자체는 필요하지만, 이만큼 크면 진동을 만드는 쪽으로 작용합니다.

그 다음으로 짚이는 것 둘:

- **Kp 380 이 높고 Kd 12 가 낮다.** 되미는 힘은 센데 그걸 눌러 줄 항이 약합니다
- **자이로 드리프트를 안 잡았다.** 목표각 `-2.0°` 를 손으로 맞춰 넣었고, 시동 시
  캘리브레이션이 없습니다

## 다음에 한다면

**1. 데드존부터 되돌린다.** 750 을 측정값에 가깝게(350 안팎) 내리고, 0 근처에서 출력이
급히 튀지 않도록 완만하게 넘어가게 합니다. 위 계산이 맞다면 여기서 제일 크게 달라집니다.

**2. Kd 를 올리고 Kp 를 내려 다시 잡는다.** 데드존을 고친 다음에 해야 의미가 있습니다.
지금은 데드존이 만드는 진동과 게인이 만드는 진동이 섞여 있어서 무엇을 고쳐서 나아졌는지
알 수가 없습니다.

**3. 시동 시 자이로 영점을 자동으로 잡는다.** 지금은 목표각이 코드에 박혀 있습니다.

**4. 서고 난 다음에 엔코더를 붙인다.** TIM3·TIM4 에 엔코더 모드로 설정만 해두고
제어 루프에서는 읽지 않습니다. 엔코더는 **서게 만드는 것이 아니라, 서 있는 로봇이
제자리를 지키게 하는 것**입니다 — 각도만 보면 넘어지지는 않아도 앞으로 스르르 밀려갑니다.
그래서 각도로 서는 것이 먼저이고, 위치 유지가 그 다음입니다.

**5. 그 뒤에 적분항을 켠다.** 남는 기울기 오차를 없애는 단계라 순서상 마지막입니다.
